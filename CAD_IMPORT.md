# Browser CAD import

The GitHub Pages browser release accepts PDF, DWG and DXF in **Upload drawings → Choose drawing files**, including mixed batches. CAD is read locally in a dedicated worker. Original files, geometry, layers, text and units stay in IndexedDB on the visitor's device; no conversion service or Python server is required. Original CAD download is available in the drawing view.

## Supported scope

- DWG signatures AC1012, AC1014, AC1015, AC1018, AC1021, AC1024, AC1027 and AC1032 (R13–2018 file formats). Newer AutoCAD applications may save the AC1032 format; the file header determines compatibility.
- ASCII and binary DXF. One model-space drawing per CAD file. Paper-space layouts are excluded from measurements.
- Common lines, polylines including bulges, arcs/circles, horizontal ellipses, non-rational B-splines, text/MTEXT/attributes, nested block inserts, block arrays, dimension blocks and face outlines. Hidden/frozen layers are omitted. Browser fonts substitute SHX/custom fonts.
- Block transforms, source colours/layers and native coordinate scale are preserved in the normalized view. Choose CAD units if `$INSUNITS` is unspecified; units are never guessed. Changing units invalidates approvals. Calibration by an actual known dimension is also available.
- Native Z is retained for paths. Non-planar paths can be inspected as drafts/3D candidates but do not participate in plan-graph joins. Distinct planar CAD elevations are isolated from each other during automatic route following.
- CAD geometry participates in the existing equipment-route suggestions, route overlays, manual correction, 3D preview and Excel workflow. Semantic matches remain provisional; importing a CAD file does not prove a pipe service or compressor connection.

File limits: 50 MB per CAD file, 200 MB expanded DXF text, two-minute worker timeout, 300,000 expanded entities, 200,000 paths and one million vertices. Complex files should be exported as a smaller model-space drawing. PDF limit remains 150 MB. An invalid import is reported as failed and does not supersede the previous valid drawing.

External references are not fetched, resolved or executed. Attach/export needed xrefs in the original CAD application. AEC/proxy objects, images, hatches, rational splines, solids and other unsupported records can be absent; import details list unsupported types. Compare the result against the original drawing. This is a model-space pipe takeoff viewer, not a full AutoCAD/BIM model renderer.

## Reader and redistribution

DWG conversion uses [dwgdxf 2.0.1](https://github.com/ducflair/dwgdxf), an MIT JavaScript/WASM wrapper around [acadrust 0.4.0](https://github.com/hakanaktt/acadrust), which is MPL-2.0. DXF parsing uses [dxf-parser 1.1.2](https://github.com/gdsestimating/dxf-parser), MIT. WASM is served from the site's own `/cad/` directory. The adapter always overrides the package's default asset location; no CDN conversion service is used.

`frontend/public/cad` includes the unmodified reader JS/WASM, original licences, corresponding MPL library source archive, wrapper source archive and third-party notices collected from the pinned Rust dependency lockfile. `python scripts/cad_third_party.py` regenerates dependency notices from checksum-verified source crates. These notices/source archives must accompany redistributed CAD assets. The separate application's code is not a modification of those library files.

The labelled DXF validation drawing is generated by this app: a 10 m + 5 m bent route in millimetres with AHU/ACCU labels. It goes through the normal importer. The **public DWG reader sample** is an upstream acadrust fixture, not a project drawing or pipe network. Its source, licence and SHA256 are in `THIRD_PARTY_NOTICES.txt`. Private project drawings are excluded from release packages.

## Validation

`npm run test:browser --prefix frontend` currently passes 94 tests, including CAD units, native Z, blocks/arrays, hidden layers, model/paper-space filtering, bulges, B-splines, rotated equipment labels, binary DXF, disconnected elevations, text attributes, invalid data, route suggestions and model previews, alongside all PDF, engineering and Excel regression checks. Production TypeScript/Vite builds pass.

Static-site browser acceptance passed: the labelled DXF imported, automatically matched AHU-GF-01 to ACCU-GF-01 with a 15.0 m bent route, displayed its overlay and 3D preview, and applied unit selection changes. The public AC1032 DWG fixture converted in the browser using same-origin WASM, displayed five native paths with millimetre units, and reported three unsupported spline records. The file input accepts PDF, DWG and DXF.
